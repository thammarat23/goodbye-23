# ส่งงานข้ามเครื่อง

เครื่องที่สองเป็นคอนเทนเนอร์บนคลาวด์ **มองไม่เห็นไดรฟ์ `G:\`** และดึงไฟล์จาก
Google Drive โดยตรงไม่ได้ (พร็อกซีบล็อก `drive.google.com` ตามนโยบายองค์กร
ส่วน API ส่งไฟล์กลับมาเป็น base64 ซึ่งใหญ่เกินรับไหว)

**ช่องทางเดียวที่ใช้ได้คือ git** ส่งไฟล์ผ่าน repo นี้

## แบ่งงานกันยังไง

| งาน | ทำที่ไหน | เพราะ |
|---|---|---|
| สำรวจว่าเล่มไหนต้อง OCR | เครื่องหลัก | ต้องเห็นไฟล์บน `G:\` |
| ดึงข้อความจาก PDF ที่มี text layer | เครื่องหลัก | เร็วมาก ไม่ต้องส่งไฟล์ไปไหน |
| **OCR เล่มที่เป็นภาพสแกน** | **เครื่องที่สอง** | หนักที่สุด 0.5 วินาที/หน้า ขนาน 4 คอร์ |
| ซ่อมข้อความ | เครื่องที่สอง | ต้องใช้พจนานุกรมไทยที่ติดตั้งไว้แล้ว |
| ทำเสียง | เครื่องหลัก | คีย์และคิวอยู่ที่นั่น |

## ส่งงานเข้าเครื่องที่สอง

วางไฟล์ที่ `inbox/` แล้ว push

```powershell
cd "G:\ไดรฟ์ของฉัน\AI-Companies\เว็บอ่านหนังสือ\tools"
git checkout claude/setup-document-scan-system-cfayx3
git pull

copy "G:\ไดรฟ์ของฉัน\หนังสือกำลังภายใน\<เรื่อง>\<เล่ม>.pdf" inbox\

git add inbox
git commit -m "ส่ง <ชื่อเล่ม> ให้เครื่องที่สอง"
git push
```

แล้วบอกในแชตว่า "ส่งไฟล์แล้ว" เครื่องที่สองจะ `git pull` มาทำต่อ

## ข้อจำกัดเรื่องขนาดไฟล์

GitHub ไม่รับไฟล์เดี่ยวเกิน **100 MB** และเตือนตั้งแต่ 50 MB

จากที่สำรวจ หนังสือส่วนใหญ่อยู่ที่ 5-10 MB ส่งได้สบาย แต่บางเล่มที่เป็น
ภาพสแกนความละเอียดสูงถึง 106 MB ซึ่งเกินขีดจำกัด

เล่มที่ใหญ่เกิน ให้หั่นก่อนส่ง

```powershell
py -3 -X utf8 -c "import fitz,sys; d=fitz.open(sys.argv[1]); n=len(d); h=n//2; a=fitz.open(); a.insert_pdf(d,0,h-1); a.save('inbox/part1.pdf'); b=fitz.open(); b.insert_pdf(d,h,n-1); b.save('inbox/part2.pdf')" "<พาธเล่มใหญ่>"
```

## อย่าลืมลบไฟล์ออกหลังทำเสร็จ

PDF ที่ค้างใน `inbox/` จะอยู่ในประวัติ git ตลอดไปและทำให้ repo บวม
พอรับผลกลับแล้วให้ลบทิ้ง

```powershell
git rm -r inbox/*.pdf
git commit -m "เก็บกวาด inbox"
git push
```
